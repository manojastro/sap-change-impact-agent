# SAP S/4HANA Change Impact & Regression Risk Agent

A release-management cockpit that answers one question for every SAP transport:
**which business processes, interfaces and tests does this change affect, and what is
the minimal high-value regression scope before release?**

Eight workflow agents analyze a transport against a simulated S/4HANA-like estate.
Deterministic graph algorithms make the decisions (impact closure, test selection,
risk scoring); the LLM layer only writes rationale text from facts the tools already
proved. High/critical changes stop at a human approval gate, release validation runs
a seeded regression simulation that catches a broken pricing change BEFORE release,
and an evaluation harness scores impact discovery and regression-scope selection
against authored ground truth.

> **MOCK MODE - SAP-LIKE SIMULATION.** This project contains no real SAP system,
> no SAP data and no licenses. All estate data is synthetic, generated by
> `simulator/generate_landscape.py`, and clearly labeled `SAP-LIKE SIMULATION`.
> Adapter interfaces exist so real SAP Cloud ALM integration can be added later.

## What it does

1. **Import** a transport request (changed objects: config items, custom code, tables,
   interfaces, roles, Fiori apps).
2. **Analyze** it through 8 persisted stages: Transport Analysis -> Custom Code ->
   Configuration -> Business Process -> Interface Impact -> Regression Scope -> Risk ->
   Validation Readiness.
3. **Discover impact** via a value-flow-aware dependency graph (NetworkX BFS with
   confidence decay), e.g. pricing condition change + Z_PRICING_DETERMINATION_EXIT ->
   Sales Order process -> Billing -> INVOIC_OUT interface.
4. **Select minimal regression scope** (4 of 17 tests for the canonical scenario,
   reason-coded per test) instead of rerun-everything.
5. **Score release risk** (0..100 weighted factors) and enforce policy: HIGH/CRITICAL
   requires human approval; rejection BLOCKS the transport.
6. **Simulate release validation**: deterministic outcomes from seeded defects; the
   canonical scenario FAILS billing amount calculation and the INVOIC_OUT payload check,
   raises defects into the platform + ALM mock, and reports criticality-weighted
   Release Confidence (51.95% for the canonical transport - caught pre-release).
7. **Evaluate itself**: `evaluation/ground_truth.json` holds known truths for 6
   transports; the runner computes recall/precision for impact discovery and test
   selection plus risk-band accuracy (all 1.0 in this build).

## Quickstart (Windows PowerShell)

Requires Python 3.11+. From the project root:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 1) create the simulated estate + sample transport (data/sap_change_impact.db)
.\.venv\Scripts\python.exe -m simulator.seed

# 2) canonical demo: import -> analysis -> approval -> validation (ASCII console output)
.\.venv\Scripts\python.exe scripts\create_high_risk_transport.py --fresh

# 3) start the cockpit
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --port 8013
# open http://127.0.0.1:8013/
```

Full walkthrough (canonical + clean control + evaluation run):
`.\.venv\Scripts\python.exe scripts\run_change_demo.py`

### Docker

```powershell
docker compose up --build      # serves on http://localhost:8013
docker compose down
```

## The canonical demo scenario

Transport `SIMK910001` changes a pricing condition config item (value-affecting) and
the custom code `Z_PRICING_DETERMINATION_EXIT`:

| Result | Value |
| --- | --- |
| Impacted processes | ORDER_TO_CASH, RECORD_TO_REPORT |
| Impacted interface | INVOIC_OUT |
| Regression scope | INVOIC_PAYLOAD_TEST, BILLING_CREATE_TEST, FI_RECONCILIATION_TEST, SO_CREATE_TEST (4/17 = 23.5%) |
| Risk | 63.5/100 = HIGH, approval required |
| Validation | BILLING_CREATE_TEST + INVOIC_PAYLOAD_TEST FAIL; confidence 51.95%; defects DEF-0001/DEF-0002 raised pre-release |

Clean control `SIMK910002` (stock sync cleanup): LOW risk 26.08, auto-approved,
1/17 tests selected, validation 100% confidence, zero defects.

## Configuration

Copy `.env.example` to `.env`. Key settings:

| Variable | Default | Purpose |
| --- | --- | --- |
| `DATABASE_URL` | `sqlite:///./data/sap_change_impact.db` | SQLite default; Postgres via `postgresql+psycopg://...` |
| `LLM_MODE` | `mock` | `mock` = deterministic facts-only writer; `openai-compatible` uses `LLM_BASE_URL`/`LLM_API_KEY`/`LLM_MODEL` |
| `CORS_ORIGINS` | localhost:8013 | Comma-separated allowlist |
| `APP_ENVIRONMENT` | `local` | Label surfaced in safe error payloads |
